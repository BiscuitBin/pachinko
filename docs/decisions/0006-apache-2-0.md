# Decision 0006: Apache-2.0

*Carried from libpawdoku's decision 0006 at `ccdd001`.*

## Context

This repository will be read and built by people outside the house: a library,
`libpachinko`, that holds the domain once the specifications define one, and a service,
`pachinko`, built around it. Both crates are `publish = false`, so neither reaches a
registry, but a licence is decided at the first commit all the same, because every later
contribution is made under it and relicensing afterwards means asking every contributor.

## Decision

Apache-2.0 for both crates. `LICENSE` at the repository root is the licence's verbatim
text; `license = "Apache-2.0"` sits in `[workspace.package]` and both crates inherit it
with `license.workspace = true`. No dual MIT/Apache, no per-file headers, no `NOTICE`
file.

Apache over MIT for two clauses MIT lacks. Section 3 grants every user a patent licence
from every contributor and terminates it for anyone who sues over the work, and section 5
places every contribution under the licence's terms automatically, which does the work a
contributor agreement would otherwise do. Not the Rust ecosystem's dual MIT/Apache: that
pairing exists so that MIT-only and GPLv2 consumers can take a crate, the consumers in
sight are the house's own, and one licence is one thing to explain. No per-file headers:
the licence's appendix makes them optional, and a header is one more thing every new file
gets wrong. No `NOTICE`: section 4(d) obliges a redistributor to carry a `NOTICE` only
where one exists, and nothing here needs attribution beyond the licence itself.

Neither crate is published. `publish = false` sits in `[workspace.package]` and both
crates inherit it with `publish.workspace = true`, so `cargo publish` refuses either one
and no crates.io release happens. The release process
([decision 0016](0016-release-process.md)) tags and releases each crate on GitHub and
keeps `publish = false`; lifting it would be a new decision, not a step in that process.

## Consequences

Apache-2.0 is incompatible with GPLv2-only programs, which cannot link it. Accepted: no
consumer in sight is one.

Every dependency must be compatible. `deny.toml` carries an allow list of licences,
Apache-2.0 with and without the LLVM exception, MIT, the BSD family, ISC, Zlib, 0BSD,
Unicode-3.0, Unlicense and CC0-1.0, and `cargo deny check licenses` at gate 13 of
`just check` fails on any crate outside it, so a copyleft dependency cannot arrive by
accident. What may be added at all is [decision 0007](0007-dependency-policy.md)'s.

A contributor's work is licensed by section 5 with no separate agreement; the repository
asks for nothing beyond the pull request.

## What would reopen this

A consumer that can only take MIT. Adding it beside Apache-2.0 would be a second licence
file, a `license = "MIT OR Apache-2.0"` line and a record superseding this one; past
contributions were made under Apache-2.0 alone, so each contributor would have to agree,
which is cheap while contributors are few and grows with every one. Or the house choosing
one licence for every repository, at which point this record follows that decision. A
wish to publish either crate to crates.io reopens the `publish = false` half: the licence
already suits a registry, but publishing is a release decision this record does not take.
